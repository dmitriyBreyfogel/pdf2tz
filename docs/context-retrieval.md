# Подготовка контекста по запросу пользователя

`POST /api/v1/pdf/context` принимает `multipart/form-data` с полями `file` (PDF)
и `prompt` (требования пользователя или поисковый вопрос). Ручка использует тот же
конвейер, что `/chunks`: обработка выполняется одним вызовом существующего pipeline,
затем полученные чанки ищутся по запросу. Пользователи, история запросов, вызов LLM
и формирование регламента здесь не реализованы.

Пример запроса:

```powershell
curl.exe -X POST http://localhost:8081/api/v1/pdf/context `
  -F "file=@instruction.pdf;type=application/pdf" `
  -F "prompt=Какие операции технического обслуживания и с какой периодичностью выполнять?"
```

Ответ содержит исходный `prompt`, `selectedChunks` с номерами страниц и путями
разделов, `totalChunkCount`, `estimatedTokenCount` и `preparedPrompt`. Последний
объединяет запрос и выбранные фрагменты с метками `[SOURCE chunk=N pages=A-B]`.
Он пригоден как текст контекста для будущего LLM-адаптера, но не содержит
утверждённого шаблона регламента или результата генерации.

Если совпадений нет, `contextAvailable=false`, список чанков и `preparedPrompt`
пусты. Пустой, непоисковый или слишком длинный `prompt` возвращает
`INVALID_PROMPT` (400); если подходящие чанки не помещаются в бюджет контекста,
возвращается `CONTEXT_BUDGET_EXCEEDED` (422).

Поиск использует BM25 по нормализованным словам и ограниченное сравнение
триграмм для близких грамматических форм. Разорванные при переносе PDF-слова
склеиваются только для поиска: исходный текст чанков сохраняется. Чанки,
состоящие лишь из заголовков, ранжируются после содержательных фрагментов.
Поиск не распознаёт синонимы и не выполняет семантический поиск на embeddings.
Чанки выбираются по релевантности, а в
`preparedPrompt` располагаются в порядке страниц исходного PDF. Бюджет охватывает
весь подготовленный текст, включая запрос и метки источников. Подсчёт использует
текущий токенизатор проекта; будущую модель и её контекстное окно нужно будет
согласовать отдельно:

```properties
pdf2tz.retrieval.max-context-tokens=8192
pdf2tz.retrieval.max-prompt-tokens=1024
pdf2tz.retrieval.max-chunks=6
```

Как и `/chunks`, этот сценарий работает только с нативным текстовым слоем PDF.
Точное чередование абзацев и таблиц по координатам страницы пока не восстановлено.
