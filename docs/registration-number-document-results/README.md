# Сквозная проверка регистрационных номеров

Проверка выполнена через `POST /api/v1/maintenance/document` с моделью
`openai/gpt-6.1-terra`. Для каждого случая сохранены исходный план,
расходники и сформированный DOCX. Внешние запросы к LLM выполнялись только
для этих двух проверок.

## `valleylab-ft10`

- Входная инструкция: `Downloads/Инструкции/1376614.pdf`.
- Из инструкции выделена модель `Valleylab FT10`.
- Публичный реестр Росздравнадзора вернул единственную действующую запись:
  `РЗН 2017/5614`.
- План содержит 24 строки, и номер проставлен в каждой строке. В `document.docx`
  номер отображается в объединённой колонке «Регистрационный номер медицинского изделия».

## `xenon-nova`

- Входная инструкция: `Downloads/Инструкции/1373196.pdf`.
- Из инструкции выделена модель `XENON NOVA`.
- Для запроса не найдено однозначной действующей записи; исторические записи с
  истёкшим сроком не используются.
- План содержит 25 строк. Во всех строках `registrationNumber` равен `null`, а
  соответствующая объединённая ячейка в `document.docx` намеренно пуста.

Это ожидаемое безопасное поведение: РУ добавляется только по единственной
действующей карточке официального реестра, а не генерируется моделью.
